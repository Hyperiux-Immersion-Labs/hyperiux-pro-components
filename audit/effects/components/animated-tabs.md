# animated-tabs (components)

## Summary

`animated-tabs` is a two-file, click-driven tabs component (`index.jsx` + `AnimatedTabsComp.jsx`) that animates a moving underline indicator and cross-fades/slides panel content with GSAP. The registry metadata is internally consistent and matches the schema in `developer-new-component.md` (correct `type`, `category`, `main`, `files`, matching `previewUrl`). Accessibility fundamentals (ARIA tablist/tab/tabpanel roles, roving `tabIndex`, arrow/Home/End keyboard navigation) are implemented correctly — better than many effects in this library. The main issues found are: (1) the docs demo route does not actually render the registry source, it renders a stale duplicate under `apps/docs/src/components/animated-tabs/` whose Tailwind breakpoints have drifted from the registry copy, and (2) there is no `prefers-reduced-motion` handling anywhere in the animation code. No continuous `requestAnimationFrame` loop exists (all motion is short GSAP tweens fired on click), so the rAF-suspension pattern from F-042 does not apply here.

## Implementation overview

- `registry/effects/components/animated-tabs/index.jsx` — default export `AnimatedTabs()`, a self-contained demo: defines a module-level `tabsData` array (3 tabs: Overview/Services/Contact, each with hardcoded light-theme JSX content) and renders `<AnimatedTabsComp tabs={tabsData} />` inside a `<section>`. No props are forwarded/exposed by this outer component.
- `registry/effects/components/animated-tabs/AnimatedTabsComp.jsx` — the actual reusable tabs primitive. Props: `tabs`, `defaultActiveIndex`, `className`, `animationType` (`"fade" | "slide"`), `slideDistance`. Renders a `role="tablist"` row of `<button role="tab">` labels plus a moving underline (`activeLineRef`) animated via `gsap.to({ x, width })`, and a stack of `role="tabpanel"` divs animated via `gsap.to`/`gsap.set` (opacity/x, with `display` toggled in `onComplete`).
- `registry.json` — `type: "registry:component"`, `category: "components"`, `tier: "pro"`, `main: "index.jsx"`, `exportName: "AnimatedTabs"` / `exportKind: "default"`, `files` array lists both `index.jsx` and `AnimatedTabsComp.jsx` with correct targets, `previewUrl: "/demo/animated-tabs"`, `dependencies: ["gsap"]`.
- `package.json` — `@hyperiux/animated-tabs`, lists both source files plus `registry.json`, `peerDependencies`-equivalent `gsap: "*"`.
- Demo route `apps/docs/src/app/(marketing)/demo/animated-tabs/page.js` imports `AnimatedTabs` from `@/components/animated-tabs` (the docs-site copy, **not** the registry copy) and wraps it with `DemoHeader`/`HeadAnim`/`SplitLine` chrome.

## Strengths

- Correct ARIA tab pattern: `role="tablist"`/`role="tab"`/`role="tabpanel"`, `aria-selected`, `aria-controls`/`aria-labelledby` wired via a shared `useId()` base, roving `tabIndex` (0 on active tab, -1 on inactive) — [`registry/effects/components/animated-tabs/AnimatedTabsComp.jsx#L172-L201`](../../../registry/effects/components/animated-tabs/AnimatedTabsComp.jsx#L172).
- Full keyboard support: ArrowRight/ArrowLeft (wrapping), Home, End, with `event.preventDefault()` and explicit `.focus()` on the newly active tab — [`registry/effects/components/animated-tabs/AnimatedTabsComp.jsx#L111-L135`](../../../registry/effects/components/animated-tabs/AnimatedTabsComp.jsx#L111).
- Defensive default-index clamping (`safeDefaultIndex`) guards against an out-of-range `defaultActiveIndex` prop or an empty `tabs` array, and the component early-returns `null` for an empty `tabs` array — [`registry/effects/components/animated-tabs/AnimatedTabsComp.jsx#L13-L16`](../../../registry/effects/components/animated-tabs/AnimatedTabsComp.jsx#L13), [`#L162`](../../../registry/effects/components/animated-tabs/AnimatedTabsComp.jsx#L162).
- `gsap.killTweensOf([currentContent, nextContent])` before starting a new panel transition, reducing (though not eliminating — see Risks) overlap artifacts from fast repeated clicks — [`AnimatedTabsComp.jsx#L46`](../../../registry/effects/components/animated-tabs/AnimatedTabsComp.jsx#L46).
- No continuous rAF loop and no global event listeners (`window`/`document`), so there is nothing that needs teardown on unmount — confirmed by reading the full file; there is no `useEffect` cleanup because none is needed.
- Registry metadata is schema-complete and self-consistent: `name` matches the folder, `main` points at an existing file, both imported files are listed in `files` with correct `target` paths, `previewUrl` matches the real demo route.

## Risks and issues

1. **[High — registry/demo drift]** The live demo page does not render the registry source. `apps/docs/src/app/(marketing)/demo/animated-tabs/page.js` imports from `@/components/animated-tabs` [`apps/docs/src/app/(marketing)/demo/animated-tabs/page.js#L1`](../../../apps/docs/src/app/(marketing)/demo/animated-tabs/page.js#L1), which resolves to the docs-site copy at `apps/docs/src/components/animated-tabs/`, not `registry/effects/components/animated-tabs/`. A `diff` of the two `AnimatedTabsComp.jsx` files shows the responsive breakpoints have already drifted: the docs copy uses `max-md:`/`max-sm:` while the registry copy (the one users actually install) uses `max-[1025px]:`/`max-md:` — [`apps/docs/src/components/animated-tabs/AnimatedTabsComp.jsx#L165-L194`](../../../apps/docs/src/components/animated-tabs/AnimatedTabsComp.jsx#L165) vs [`registry/effects/components/animated-tabs/AnimatedTabsComp.jsx#L165-L194`](../../../registry/effects/components/animated-tabs/AnimatedTabsComp.jsx#L165). This means the public demo is not an accurate preview of what `npx hyperiux add animated-tabs` actually installs — a purchaser previewing responsive behavior on the demo page is not seeing the registry component's real breakpoints. This is a registry-schema/process violation per `developer-new-component.md`'s "two locations must stay in sync" model, not a schema-field error, so I am rating it High rather than Critical (nothing crashes, no CLI install is broken, but the sold experience and shipped experience differ).
2. **[Medium — no reduced-motion handling]** Neither file checks `prefers-reduced-motion` (no `matchMedia` call anywhere in the component; confirmed via `grep -rn "prefers-reduced-motion\|matchMedia"` returning nothing under the effect folder). Every tab switch always runs the full GSAP slide/fade timeline (`animateContent`, [`AnimatedTabsComp.jsx#L38-L101`](../../../registry/effects/components/animated-tabs/AnimatedTabsComp.jsx#L38)) and the indicator always tweens with `duration: 0.45` ([`#L30-L35`](../../../registry/effects/components/animated-tabs/AnimatedTabsComp.jsx#L30)) regardless of user OS motion preference.
3. **[Medium — contrast on inactive tab labels]** Inactive tab labels use `text-black/50` on a white background ([`AnimatedTabsComp.jsx#L179-L183`](../../../registry/effects/components/animated-tabs/AnimatedTabsComp.jsx#L179)), i.e. ~50%-opacity black text (~3.9:1 contrast against white). At the rendered size (`text-[1.2vw]`, non-bold) this is below the WCAG AA 4.5:1 threshold for normal text and only borderline-qualifies as "large text" (18.66px bold / 24px regular) depending on viewport width, so on many viewport widths it fails AA contrast for low-vision users reading un-selected tab labels.
4. **[Low — code style deviation]** `AnimatedTabsComp.jsx` is formatted with 1-space indentation and no space after `:`/`,` in several spots (e.g. `ease:"power3.out"`, `import gsap from"gsap"`), diverging from the 2-space, space-after-colon style used by sibling components such as `animated-faq/index.jsx` — compare [`registry/effects/components/animated-tabs/AnimatedTabsComp.jsx#L1-L36`](../../../registry/effects/components/animated-tabs/AnimatedTabsComp.jsx#L1) against [`registry/effects/components/animated-faq/index.jsx#L1-L14`](../../../registry/effects/components/animated-faq/index.jsx#L1). Violates CODING_STANDARDS.md's implicit house style (readability, consistent formatting); purely cosmetic, does not affect behavior.
5. **[Low — theoretical rapid-click transition edge case, unconfirmed]** `handleTabClick` calls `animateContent(activeTab, index)` then `moveActiveLine(index)` then `setActiveTab(index)` — [`AnimatedTabsComp.jsx#L103-L109`](../../../registry/effects/components/animated-tabs/AnimatedTabsComp.jsx#L103). `killTweensOf` only targets the two panels involved in the *current* transition call, not any panel that may still be mid-tween from a transition started (and not yet completed) one click prior on a third tab. In principle very fast sequential tab switches (e.g. holding ArrowRight) could leave a panel's `display`/`opacity` in an intermediate state if a new transition starts before the previous `onComplete` fires. I could not confirm this in a running browser (no automated interaction test exists in this repo for this component), so this is flagged as a low-confidence, low-severity risk rather than a verified defect.

## Accessibility assessment

Solid for a click-only widget: correct roles, `aria-selected`, `aria-controls`/`aria-labelledby` pairing via `useId()`, roving `tabIndex`, and full arrow/Home/End keyboard support with explicit focus management ([`AnimatedTabsComp.jsx#L111-L135`](../../../registry/effects/components/animated-tabs/AnimatedTabsComp.jsx#L111), [`#L169-L201`](../../../registry/effects/components/animated-tabs/AnimatedTabsComp.jsx#L169)). Panels are focusable (`tabIndex={0}` on `role="tabpanel"`, [`#L202`](../../../registry/effects/components/animated-tabs/AnimatedTabsComp.jsx#L202)) which is acceptable per WAI-ARIA APG when panel content itself has no single obvious focus target. Gaps: no `prefers-reduced-motion` handling (Medium finding above) and the inactive-label contrast issue (Medium finding above). No `aria-live` region — not needed here since content swap is user-triggered and visually obvious, not an async update.

## Performance assessment

No continuous rAF loop — all motion is short, click-triggered GSAP tweens (`gsap.to`/`gsap.set`), so the F-042 rAF-suspension pattern is not applicable and its absence is not a finding here, consistent with the task's own instruction to only flag missing rAF-suspension when a continuous loop genuinely exists. All tab panels are mounted simultaneously (hidden via `display:none` for inactive ones, [`AnimatedTabsComp.jsx#L150-L159`](../../../registry/effects/components/animated-tabs/AnimatedTabsComp.jsx#L150)) rather than lazily mounted on first activation; fine at the demo's 3-tab scale, would not scale gracefully to a very large tab count, but that's a hypothetical not present in the shipped demo. No automated performance test exists in this repo to verify animation frame timing — not independently measured.

## SEO and content-surface assessment

All tab panel content is present in the DOM at all times (hidden via CSS, not conditionally rendered/unmounted) — [`AnimatedTabsComp.jsx#L150-L159`](../../../registry/effects/components/animated-tabs/AnimatedTabsComp.jsx#L150), [`#L204-L207`](../../../registry/effects/components/animated-tabs/AnimatedTabsComp.jsx#L204). This means content in non-default tabs (Services, Contact copy) is crawlable/indexable by search engines even though visually hidden, which is generally favorable for SEO versus a component that unmounts inactive panels. No `next/head`/metadata concerns inside the component itself; the demo page's `generateMetadata` is handled separately at the page level ([`apps/docs/src/app/(marketing)/demo/animated-tabs/page.js#L34-L36`](../../../apps/docs/src/app/(marketing)/demo/animated-tabs/page.js#L34)) and is out of scope for the component itself.

## Responsive / mobile / touch behavior assessment

Layout uses `vw`-based sizing with `max-[1025px]:`/`max-md:` breakpoint overrides throughout (registry copy) — e.g. [`AnimatedTabsComp.jsx#L165-L194`](../../../registry/effects/components/animated-tabs/AnimatedTabsComp.jsx#L165). The tablist row has `overflow-x-auto` ([`#L167`](../../../registry/effects/components/animated-tabs/AnimatedTabsComp.jsx#L167)) so a tab set too wide for the viewport scrolls horizontally rather than wrapping or clipping — reasonable for touch. Interaction is standard `onClick`/`onKeyDown` on native `<button>` elements, which works uniformly across mouse, touch, and keyboard without any custom touch-gesture code to audit. As noted in Risk #1, the demo route users actually see is running the docs-site copy with different (older) breakpoints than what installs via the CLI, so responsive QA done against the live demo does not verify the shipped registry component.

## Maintainability and code-quality assessment

`AnimatedTabsComp.jsx` is a single ~215-line file, reasonably organized (state/refs, helper functions, event handlers, effect, render) though it does not follow the section-comment convention (`// State & Refs`, `// Effects`, etc.) suggested in `CODING_STANDARDS.md` §1. Formatting inconsistency (1-space indent, missing spaces after `:`/`,`) noted as Risk #4 is the main code-quality nit; functionally the code is straightforward and readable. `index.jsx` hardcodes demo content directly in the distributed entry file rather than accepting the tabs data as an external prop at the top level — this is a common, accepted pattern in this registry (consumers are expected to edit `index.jsx` post-install), not a defect, but worth noting that `AnimatedTabs()` itself takes no props, so the reusable/configurable surface is entirely in `AnimatedTabsComp`, not `AnimatedTabs`.

## Security and dependency concerns

No secrets, tokens, or API keys in source. No `dangerouslySetInnerHTML`, no raw HTML string interpolation, no unescaped user input rendered anywhere in either file — `tab.content` is always a JSX value defined by the integrating developer, not user-supplied at runtime. Sole dependency is `gsap`, declared consistently in `registry.json` (`dependencies: ["gsap"]`), `package.json` (`dependencies.gsap: "*"`), and actually imported and used in `AnimatedTabsComp.jsx#L4`. No unused or undeclared dependencies found.

## Browser compatibility considerations

Uses `offsetLeft`/`offsetWidth` (universally supported) for indicator positioning ([`AnimatedTabsComp.jsx#L25-L35`](../../../registry/effects/components/animated-tabs/AnimatedTabsComp.jsx#L25)) and GSAP for all animation, which handles cross-browser transform/opacity tweening itself. No use of newer/less-supported CSS or JS APIs (no `:has()`, no container queries, no experimental APIs) in the component code. `useId()` requires React 18+; not flagged as an issue since this is a baseline requirement across the registry, not specific to this effect.

## What was checked and found clean

- `registry.json` schema completeness against `developer-new-component.md`: `name` matches folder, `type` is exactly `"registry:component"`, `category` is exactly `"components"`, `main` (`index.jsx`) exists, both files in the `files` array exist and have correct `target` paths, `previewUrl` (`/demo/animated-tabs`) matches the real demo route folder, `tier: "pro"` is a valid enum value, `exportName`/`exportKind` (`AnimatedTabs`/`default`) match the actual `export default function AnimatedTabs()` in `index.jsx`.
- `package.json`: valid `@hyperiux/animated-tabs` name, correct `files` list, `gsap` dependency declared.
- Cleanup on unmount: no `addEventListener`, no `setInterval`/`setTimeout`, no rAF loop, no WebGL resources anywhere in either file — nothing requires a cleanup function, and none is missing.
- No continuous rAF loop exists, so the F-042 rAF-suspension pattern (`createSuspendedRaf`/`createVisibilityGate`) is correctly not present — its absence is not a defect per the audit's own rubric instruction.
- No hardcoded secrets/tokens; no XSS-able unescaped input.
- Public mirror (`apps/docs/public/r/animated-tabs.json`) matches `registry.json` on all content-relevant fields (`name`, `dependencies`, `exportName`, `exportKind`, `tier`, `version`, file list). The only difference is the `target` path format (`components/hyperiux/index.jsx` in the public mirror vs. `src/components/effects/animated-tabs/index.jsx` in the source `registry.json`); the same transformation pattern was observed on `animated-form`'s public mirror, indicating this is a systemic build-script `target`-flattening behavior rather than an animated-tabs-specific error. Flagged as an informational drift note only, not a scored finding, since verifying the build script's intended behavior is outside this audit's file set.

## Suggested improvements and remediation priorities

No code was changed as part of this audit, per instructions. If addressed later, changes must be verified not to break UI, responsiveness, or registry install behavior (per `CHANGE_GUIDELINES.md`) before merging.

1. **Highest priority:** Point the demo route (`apps/docs/src/app/(marketing)/demo/animated-tabs/page.js`) at the registry source (or resync the docs-site copy in `apps/docs/src/components/animated-tabs/` from `registry/effects/components/animated-tabs/`) so the public preview matches what the CLI installs. This is the only finding in this report with a High severity tag.
2. Add a `prefers-reduced-motion` check (e.g. `window.matchMedia('(prefers-reduced-motion: reduce)')`) that shortens/skips the indicator and panel tweens, consistent with how other motion-heavy effects in this registry should behave.
3. Darken the inactive-tab label color (e.g. from `black/50` to something closer to `black/65`+) to clear WCAG AA contrast at normal text sizes.
4. Reformat `AnimatedTabsComp.jsx` to the 2-space / spaced-punctuation style used elsewhere in the registry for consistency (cosmetic only).
5. Optional/low-priority: consider whether `killTweensOf` scope should track all panels rather than just the two involved in the immediate transition, to fully close the rapid-click edge case in Risk #5 — only worth pursuing if it can be reproduced.
