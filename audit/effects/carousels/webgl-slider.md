# webgl-slider (carousels)

## Summary

`webgl-slider` is a scroll-driven, WebGL-rendered "fold" carousel: 11 planes textured with images, arced in world space, folding along an edge as they scroll past, with a GSAP-driven scroll-snap-to-viewport behavior layered on top of native scroll (optionally cooperating with a `lenis` instance if one exists in the tree). The core WebGL implementation (`WebGLSliderComp.jsx`) is well-built for a continuous-scroll shader effect — shared geometry, per-mesh visibility culling, careful cleanup/disposal, and a scroll-index-driven `aria-live` announcement for screen readers. The registry packaging around it, however, has a real defect (`package.json` points at a source file that does not exist anywhere in the folder, which would break the documented `npm pack` distribution step) and the shipped `index.jsx` hardcodes all slide content with zero customization surface (no `className`, no props), which conflicts with this repo's own component-authoring rules in `developer-new-component.md`. There is no `prefers-reduced-motion` handling and no rAF-suspension-on-hidden pattern, both of which matter here because the effect runs an unconditional `requestAnimationFrame` loop for as long as the component is mounted.

## Implementation overview

- `registry/effects/carousels/webgl-slider/index.jsx` — the distributed default export (`WebGLSlider`). Hardcodes an array of 11 `picsum.photos` seed images with placeholder captions, does a `< 768px` mobile check, and renders either a "Open on desktop" fallback or `WebGLSliderComp`. [registry/effects/carousels/webgl-slider/index.jsx#L5](../../../registry/effects/carousels/webgl-slider/index.jsx#L5), [registry/effects/carousels/webgl-slider/index.jsx#L19-L46](../../../registry/effects/carousels/webgl-slider/index.jsx#L19-L46)
- `registry/effects/carousels/webgl-slider/WebGLSliderComp.jsx` — the actual Three.js scene: a custom vertex shader computing a cylindrical "fold" bend plus mouse-proximity bulge, a fragment shader doing cover-fit UV sampling, a scroll-position → mesh-arc-position mapping (`tick()`), a GSAP-based scroll-snap-to-nearest-viewport effect, and DOM text overlays kept in sync with each mesh's screen projection. [registry/effects/carousels/webgl-slider/WebGLSliderComp.jsx#L82-L573](../../../registry/effects/carousels/webgl-slider/WebGLSliderComp.jsx#L82)
- `registry/effects/carousels/webgl-slider/package.json` — npm packaging metadata for `npm pack` distribution.
- `registry/effects/carousels/webgl-slider/registry.json` — CLI/registry metadata.
- Demo route: `apps/docs/src/app/(marketing)/demo/webgl-slider/page.js`, which does **not** import the registry copy — it imports a separate, docs-site-local copy at `apps/docs/src/components/webgl-slider/` (per the documented workflow in `developer-new-component.md`, where `src/components/` is the "build and test" copy and `registry/effects/` is the distribution copy).

## Strengths

- Shared `THREE.PlaneGeometry` reused across all 11 meshes instead of allocating one geometry per slide — good memory discipline. [registry/effects/carousels/webgl-slider/WebGLSliderComp.jsx#L241](../../../registry/effects/carousels/webgl-slider/WebGLSliderComp.jsx#L241)
- Per-mesh visibility culling (`mesh.visible`) skips text-DOM and fold-uniform work for offscreen slides inside the same `tick()` pass, avoiding unnecessary per-frame work as the loop grows. [registry/effects/carousels/webgl-slider/WebGLSliderComp.jsx#L401-L435](../../../registry/effects/carousels/webgl-slider/WebGLSliderComp.jsx#L401-L435)
- Thorough cleanup: cancels the rAF, removes both `mousemove`/`resize` window listeners, removes the renderer DOM node, disposes every texture, every material, the shared geometry, and the renderer itself, and resets the `document.body.style.height` hack it applies. [registry/effects/carousels/webgl-slider/WebGLSliderComp.jsx#L479-L517](../../../registry/effects/carousels/webgl-slider/WebGLSliderComp.jsx#L479-L517)
- Named event handlers throughout (`onMouseMove`, `onResize`, `handleScroll`) matching `CODING_STANDARDS.md` §3 "Name all inline functions."
- Live-region accessibility for slide changes: an `aria-live="polite"`/`aria-atomic="true"` region announces the active slide's caption and position as the user scrolls, driven off the same index computed for rendering — a real (if partial) screen-reader accommodation that most WebGL slider implementations skip entirely. [registry/effects/carousels/webgl-slider/WebGLSliderComp.jsx#L546-L548](../../../registry/effects/carousels/webgl-slider/WebGLSliderComp.jsx#L546-L548)
- Responsive tuning: `CARD_W`/`CARD_H`/`GAP`/arc radii/offsets are all branched by `mobileViewport`/`isTablet`/`isCompact`, not a single fixed desktop layout crammed into smaller viewports. [registry/effects/carousels/webgl-slider/WebGLSliderComp.jsx#L207-L214](../../../registry/effects/carousels/webgl-slider/WebGLSliderComp.jsx#L207-L214), [registry/effects/carousels/webgl-slider/WebGLSliderComp.jsx#L311-L321](../../../registry/effects/carousels/webgl-slider/WebGLSliderComp.jsx#L311-L321)
- Two explanatory "why" comments (Lenis-optional coexistence, and native-scroll smoothing) that follow `CODING_STANDARDS.md` §7's "keep comments that explain why." [registry/effects/carousels/webgl-slider/WebGLSliderComp.jsx#L100-L104](../../../registry/effects/carousels/webgl-slider/WebGLSliderComp.jsx#L100-L104), [registry/effects/carousels/webgl-slider/WebGLSliderComp.jsx#L327-L330](../../../registry/effects/carousels/webgl-slider/WebGLSliderComp.jsx#L327-L330)

## Risks and issues

### 1. `package.json` references a source file that does not exist in the folder — High

`registry/effects/carousels/webgl-slider/package.json` sets `"main": "webgl-slider.jsx"` and `"files": ["webgl-slider.jsx", "registry.json"]`. [registry/effects/carousels/webgl-slider/package.json#L5-L9](../../../registry/effects/carousels/webgl-slider/package.json#L5-L9). No file named `webgl-slider.jsx` exists anywhere in the folder — the actual source files are `index.jsx` and `WebGLSliderComp.jsx`. Per `developer-new-component.md` Step 9, `npm pack` is run directly inside this folder to produce the distributable `.tgz`, and npm's `files` field governs exactly what gets included. As written, `npm pack` would produce a tarball that omits both real source files entirely and whose declared `main` entry point doesn't exist. This is a registry-schema/packaging violation that would silently break the tarball-based distribution channel documented in Steps 5 and 9 of `developer-new-component.md`.

### 2. Distributed `index.jsx` accepts no props at all — Medium

`developer-new-component.md` Step 1 requires: *"Accept a `className` prop so users can override styles"* and *"No hardcoded colors — use props with sensible defaults."* [developer-new-component.md#L66-L70](../../../developer-new-component.md#L66-L70). The shipped `WebGLSlider` component takes zero props — the 11 slide images/captions are hardcoded to `picsum.photos` seed URLs, and there is no `className` pass-through anywhere in the returned JSX. [registry/effects/carousels/webgl-slider/index.jsx#L5-L19](../../../registry/effects/carousels/webgl-slider/index.jsx#L5), [registry/effects/carousels/webgl-slider/index.jsx#L43-L46](../../../registry/effects/carousels/webgl-slider/index.jsx#L43-L46). A user who installs this via the CLI gets a slider of demo placeholder photos and has to edit the installed source directly to use their own images or restyle it — there is no supported customization path, even though the internal `WebGLSliderComp` already accepts an `images` prop and could trivially be forwarded.

### 3. Continuous rAF loop with no visibility/off-screen suspension — Medium

`tick()` unconditionally re-queues itself via `requestAnimationFrame(tick)` for the entire mounted lifetime of the component, regardless of tab visibility or scroll position. [registry/effects/carousels/webgl-slider/WebGLSliderComp.jsx#L333-L334](../../../registry/effects/carousels/webgl-slider/WebGLSliderComp.jsx#L333-L334), [registry/effects/carousels/webgl-slider/WebGLSliderComp.jsx#L467-L469](../../../registry/effects/carousels/webgl-slider/WebGLSliderComp.jsx#L467-L469). Per `registry/effects/_shared/README.md`, the `createSuspendedRaf`/`createVisibilityGate` pattern was rolled out to `webgl/`, `cursor/`, `backgrounds/`, and `scroll/` categories under F-042, but not `carousels/` — so this is not a regression against a prior standard, but it is a genuine continuous-rAF effect (11 mesh updates, shader uniform writes, and a full render call every frame) with no equivalent tab-hidden pause, meaning it keeps doing full per-frame work even when the browser tab is backgrounded.

### 4. `THREE.WebGLRenderer` instantiation has no failure handling — Medium

`new THREE.WebGLRenderer({...})` is called with no `try/catch`. [registry/effects/carousels/webgl-slider/WebGLSliderComp.jsx#L178-L181](../../../registry/effects/carousels/webgl-slider/WebGLSliderComp.jsx#L178-L181). On a browser/environment where WebGL context creation fails (WebGL disabled by policy, exhausted context limit, certain locked-down browsers), this throws synchronously inside `useEffect`, with no fallback UI — the desktop code path has no equivalent to the "Open on desktop" graceful-degradation message shown for the mobile viewport case.

### 5. Global `document.body.style.height` mutation — Medium

The effect sets `document.body.style.height` directly on mount and clears it on unmount to create scroll room for the effect. [registry/effects/carousels/webgl-slider/WebGLSliderComp.jsx#L299](../../../registry/effects/carousels/webgl-slider/WebGLSliderComp.jsx#L299), [registry/effects/carousels/webgl-slider/WebGLSliderComp.jsx#L516](../../../registry/effects/carousels/webgl-slider/WebGLSliderComp.jsx#L516). This is a document-global side effect, not scoped to the component's own container — if any other component/effect on the host page also sets `body.style.height`, or the page has its own layout relying on body height, mounting/unmounting this component will clobber it. This is inherent to the "full-page scroll-jacking slider" design (it needs scroll distance from somewhere), but it's undocumented anywhere in the component and has no guard against colliding with sibling effects.

### 6. `package.json` uses `dependencies` instead of `peerDependencies`, and omits `react` — Low/Medium

`developer-new-component.md` Step 5 states the `package.json`'s job is `peerDependencies` listing `react` plus major packages like `gsap`. [developer-new-component.md#L159-L167](../../../developer-new-component.md#L159-L167). This file instead declares `three`, `gsap`, `lenis` under `dependencies` and never lists `react` at all. [registry/effects/carousels/webgl-slider/package.json#L14-L18](../../../registry/effects/carousels/webgl-slider/package.json#L14-L18). Not the file that breaks CLI install (that's driven by `registry.json`'s own `dependencies` array, which is correct), but it's a real conformance gap in the npm-tarball packaging path.

### 7. Dead/no-op helper — Low

`getMediaProxyUrl(src)` is defined and called but simply returns `src` unchanged — a vestigial stub, apparently left over from the docs-site copy which does proxy images through `/api/media-proxy`. [registry/effects/carousels/webgl-slider/WebGLSliderComp.jsx#L78-L80](../../../registry/effects/carousels/webgl-slider/WebGLSliderComp.jsx#L78-L80), [registry/effects/carousels/webgl-slider/WebGLSliderComp.jsx#L260](../../../registry/effects/carousels/webgl-slider/WebGLSliderComp.jsx#L260). Minor "dead code is noise" deviation from `CODING_STANDARDS.md` §Core Principles item 4.

### 8. `<h1>` used for every slide caption (11 instances in the DOM) — Low

Each of the 11 slides renders an `<h1>` for its caption text (only one visible at a time via `display: none`/`block` toggling in the rAF loop). [registry/effects/carousels/webgl-slider/WebGLSliderComp.jsx#L560-L565](../../../registry/effects/carousels/webgl-slider/WebGLSliderComp.jsx#L560-L565). Multiple `<h1>` elements in one document harms the page's heading outline for assistive tech and SEO crawlers, even though only one is visually displayed at a time. Notably, the parallel docs-site copy at `apps/docs/src/components/webgl-slider/WebGLSliderComp.jsx` (lines 562-564) uses `<p>` for the same markup — meaning the registry (distribution) copy and the docs-site copy have drifted on this specific detail, and the registry version is the more accessibility-incorrect of the two.

### 9. Hardcoded colors in fallback UI — Low

`bg-[#050505]`, `text-white/35`, `text-white/55` etc. are hardcoded in the mobile fallback markup in both `index.jsx` and `WebGLSliderComp.jsx`. [registry/effects/carousels/webgl-slider/index.jsx#L31-L37](../../../registry/effects/carousels/webgl-slider/index.jsx#L31-L37), [registry/effects/carousels/webgl-slider/WebGLSliderComp.jsx#L521-L529](../../../registry/effects/carousels/webgl-slider/WebGLSliderComp.jsx#L521-L529). Minor deviation from the "no hardcoded colors" guidance in `developer-new-component.md`, though defensible for a full-bleed dark fallback screen.

## Accessibility assessment

- **Positive:** an `aria-live="polite"`/`aria-atomic="true"` region announces the active slide's caption and position ("PR.00 /10, slide 1 of 11") as the user scrolls, computed from the same `activeIndex` state driving the visual mesh selection. [registry/effects/carousels/webgl-slider/WebGLSliderComp.jsx#L534-L548](../../../registry/effects/carousels/webgl-slider/WebGLSliderComp.jsx#L534-L548)
- **Gap:** the images themselves are rendered as WebGL textures inside a `<canvas>`, not `<img>` tags, so there is no `alt` text conveying image content to screen readers or non-visual agents — only the numeric caption ("PR.00 /10") is announced, which is decorative rather than descriptive. This is a structural limitation of canvas/WebGL-rendered image content generally, not unique to this component, but it means a screen-reader user learns only "there is a slide N of 11" and never what the photo depicts.
- **Gap:** no keyboard-specific affordance is offered beyond what native scrolling already provides — Page Down/Space/Arrow keys will move `window.scrollY` and the effect reacts to that scroll (since it reads `window.scrollY` directly, [registry/effects/carousels/webgl-slider/WebGLSliderComp.jsx#L107-L108](../../../registry/effects/carousels/webgl-slider/WebGLSliderComp.jsx#L107-L108)), so basic keyboard scrolling does work, but there's no way to jump directly to a specific slide via keyboard, and no focus target at all (no interactive controls exist to focus).
- **Gap:** multiple `<h1>` elements in the DOM (Risk #8 above) is a heading-hierarchy problem for screen-reader document-outline navigation.
- No `prefers-reduced-motion` handling anywhere in the component — see Performance assessment below.

## Performance assessment

- Continuous `requestAnimationFrame` loop for the full mounted lifetime, uncapped by visibility (Risk #3). No automated way to measure the actual paint/frame cost was run as part of this audit — this is a static-code observation, not a profiled measurement.
- `renderer.setPixelRatio(Math.min(window.devicePixelRatio, 2))` caps device pixel ratio sensibly. [registry/effects/carousels/webgl-slider/WebGLSliderComp.jsx#L183](../../../registry/effects/carousels/webgl-slider/WebGLSliderComp.jsx#L183)
- Textures set `generateMipmaps = false` and use `LinearFilter` for both min/mag — reasonable for a small fixed set of full-screen-ish planes, avoids mipmap-generation cost per load. [registry/effects/carousels/webgl-slider/WebGLSliderComp.jsx#L266-L268](../../../registry/effects/carousels/webgl-slider/WebGLSliderComp.jsx#L266-L268), [registry/effects/carousels/webgl-slider/WebGLSliderComp.jsx#L285-L287](../../../registry/effects/carousels/webgl-slider/WebGLSliderComp.jsx#L285-L287)
- Per-frame work is bounded to `images.length` (11) mesh updates — no unbounded growth, no leaked per-frame allocations observed (vector math reuses pre-allocated `THREE.Vector2/Vector3` instances declared outside the loop, e.g. `targetUv`, `mouseWorldDir`, `mouseWorldPos`). [registry/effects/carousels/webgl-slider/WebGLSliderComp.jsx#L303-L304](../../../registry/effects/carousels/webgl-slider/WebGLSliderComp.jsx#L303-L304), [registry/effects/carousels/webgl-slider/WebGLSliderComp.jsx#L325](../../../registry/effects/carousels/webgl-slider/WebGLSliderComp.jsx#L325)
- No `prefers-reduced-motion` handling: the fold-distortion, hover-bulge, and GSAP scroll-snap animation all run unconditionally, regardless of the user's OS-level reduced-motion preference — a real gap given this is a fairly aggressive full-viewport scroll-jacking + shader-distortion effect.

## SEO and content-surface assessment

- Slide captions ("PR.00 /10" etc.) carry no real semantic/SEO content — they're decorative index labels, not descriptive text, so there's little to index either way.
- Multiple `<h1>` tags per page (Risk #8) is a minor SEO/heading-outline concern if this component is embedded on a page that also has its own single, canonical `<h1>`.
- Images are loaded via `THREE.TextureLoader` into a `<canvas>`, so they are invisible to search engine image indexing and to any HTML-only content extraction — expected/inherent to WebGL image carousels, not a defect specific to this implementation.

## Responsive / mobile / touch behavior assessment

- Explicit `< 768px` mobile breakpoint check bails out of the WebGL scene entirely and shows a static "Open on desktop" message, in both `index.jsx` and `WebGLSliderComp.jsx`. [registry/effects/carousels/webgl-slider/index.jsx#L20-L27](../../../registry/effects/carousels/webgl-slider/index.jsx#L20-L27), [registry/effects/carousels/webgl-slider/WebGLSliderComp.jsx#L89-L98](../../../registry/effects/carousels/webgl-slider/WebGLSliderComp.jsx#L89-L98)
- Note this check is duplicated in two places (parent `index.jsx` and `WebGLSliderComp.jsx`) with the same 768px threshold and near-identical fallback markup — a `CODING_STANDARDS.md` §3 "extract repeated guards" candidate, though each check lives in a separately-mountable component so some duplication is defensible.
- Tablet breakpoint (`768–1025px`) gets its own `CARD_W`/`CARD_H`/`GAP`/arc-radius tuning distinct from both mobile and desktop. [registry/effects/carousels/webgl-slider/WebGLSliderComp.jsx#L207-L214](../../../registry/effects/carousels/webgl-slider/WebGLSliderComp.jsx#L207-L214)
- Because the component fully bails to a static message below 768px, there is no touch-drag/swipe interaction to evaluate — the effect is desktop/scroll-only by design, and the mobile message communicates that limitation to the end user.
- `window.addEventListener("resize", onResize)` recalculates camera aspect and renderer size, but does **not** recompute `CARD_W`/`CARD_H`/`GAP`/`mobileViewport`/`isTablet`/`arcRadiusX` etc., all of which are captured once at effect-setup time. [registry/effects/carousels/webgl-slider/WebGLSliderComp.jsx#L207-L214](../../../registry/effects/carousels/webgl-slider/WebGLSliderComp.jsx#L207-L214), [registry/effects/carousels/webgl-slider/WebGLSliderComp.jsx#L471-L477](../../../registry/effects/carousels/webgl-slider/WebGLSliderComp.jsx#L471-L477). Resizing a desktop window down across the 768px/1025px breakpoints without a full remount (e.g. rotating a tablet, or a desktop window drag) will not re-tier the layout — the `isMobile` state re-render does force a full effect remount once the 768px boundary is crossed (dependency array includes `isMobile`, [registry/effects/carousels/webgl-slider/WebGLSliderComp.jsx#L518](../../../registry/effects/carousels/webgl-slider/WebGLSliderComp.jsx#L518)), but crossing the 768/1025 tablet boundary without crossing the mobile boundary leaves stale tier constants in place until a full remount happens for some other reason. This is a real but bounded edge case (window-resize across a specific breakpoint, not covered by an automated test in this repo).

## Maintainability and code-quality assessment

- `WebGLSliderComp.jsx` follows the file-structure convention from `CODING_STANDARDS.md` §1 reasonably well: shaders at module level with `/* glsl */` tags, component below, effects grouped, cleanup returned. [registry/effects/carousels/webgl-slider/WebGLSliderComp.jsx#L8-L54](../../../registry/effects/carousels/webgl-slider/WebGLSliderComp.jsx#L8-L54) (vertex shader), [registry/effects/carousels/webgl-slider/WebGLSliderComp.jsx#L56-L73](../../../registry/effects/carousels/webgl-slider/WebGLSliderComp.jsx#L56-L73) (fragment shader)
- GLSL uniform declarations are not column-aligned per `CODING_STANDARDS.md` §4 ("Align `uniform` declarations"). [registry/effects/carousels/webgl-slider/WebGLSliderComp.jsx#L9-L12](../../../registry/effects/carousels/webgl-slider/WebGLSliderComp.jsx#L9-L12) — a Low-severity style nit.
- Several magic numbers in the shader/tick math (`0.7`, `0.9`, `0.1`, `3.14159`, `2.0`, `0.12`, `0.15`, `150` ms debounce, `1000` ms Lenis-resume delay, `0.6` s snap duration) are not lifted into named constants per `CODING_STANDARDS.md` §2's "Magic Numbers → Named Constants" rule, though several of the more load-bearing ones (`SCROLL_LERP`, `HALF_PI`, `CARD_W_OFFSET`, `CARD_H_75`) *are* named. Mixed compliance — Low.
- The GLSL fold math itself (arc-length bend approximation) has no inline comments explaining the physical model (`A`, `R`, `theta`, `t_bend`, `t_straight` are all unexplained single/double-letter variables), which makes it hard to safely modify without reverse-engineering the trigonometry — this is exactly the kind of "why" comment `CODING_STANDARDS.md` §7 calls for, and it's absent here. [registry/effects/carousels/webgl-slider/WebGLSliderComp.jsx#L28-L44](../../../registry/effects/carousels/webgl-slider/WebGLSliderComp.jsx#L28-L44)
- The registry copy and the `apps/docs/src/components/webgl-slider/` copy have drifted (Risk #8's `<h1>`/`<p>` diff is the only functional difference found in `WebGLSliderComp.jsx`; the two `index.jsx` files differ by design since the docs copy proxies real CDN assets through `/api/media-proxy` while the registry copy uses `picsum.photos` demo placeholders — that difference is expected per the documented two-copy workflow, not a bug).

## Browser compatibility considerations

- Requires WebGL support with no feature-detection or graceful fallback if `WebGLRenderer` construction throws (Risk #4).
- Relies on standard, broadly-supported browser APIs otherwise: `IntersectionObserver` is not used at all (consistent with the F-042 scope note — this category doesn't have the visibility-gate pattern), `ResizeObserver` is not used (plain `window resize` listener instead), `matchMedia` is not used (no reduced-motion check).
- `document.documentElement.scrollTop` fallback alongside `window.scrollY` is a reasonable defensive pattern for older browser scroll-position quirks. [registry/effects/carousels/webgl-slider/WebGLSliderComp.jsx#L107-L108](../../../registry/effects/carousels/webgl-slider/WebGLSliderComp.jsx#L107-L108)

## Suggested improvements and remediation priorities

No code was changed as part of this audit. In priority order, if this component were remediated:

1. **Fix `package.json`** — point `main`/`files` at the real files (`index.jsx`, `WebGLSliderComp.jsx`, `registry.json`), following Step 5/9 of `developer-new-component.md`, so `npm pack` produces a working tarball. (Addresses Risk #1, High.)
